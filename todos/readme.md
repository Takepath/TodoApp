# Level 4 README

## **Todoアプリ**

## アプリ概要
ブラウザで動作するTodo管理アプリ

## 主な機能
Todo追加・編集・削除
表示のソート・フィルター

## 使用技術
HTML / CSS / JavaScript / FullCalendar7.1.0 / PHP

## データ構造
<dl>
    <dt>Todoクラス : </dt>
    <dt>メンバ変数 : </dt>
        <dd>id : index番号に依存しない固有ID</dd>
        <dd>title : Todoの見出し。</dd>
        <dd>completed : Todoの完了状態管理フラグ。初期状態はfalse。</dd>
        <dd>dueDate : String型の日付。"2026-09-25"形式。</dd>
        <dd>dueTime : String型の時間。"10:00"形式。</dd>
        <dd>createdAt : インスタンスが作成された時間。Dateオブジェクト形式。</dd>
    <dt>メソッド : </dt>
        <dd>なし</dd>
    <dt>Todo配列 : </dt>
        <dd>Todoクラスを格納する配列。</dd>
    <dt>localStrage "todo" : </dt>
        <dd>Todo配列を保存するローカルストレージ。</dd>
</dl>

## 工夫した点
Reactのようなコンポーネント指向プログラムを目指して作成した点

## 苦労した点
API取得データに切り替える処理<br>
FullCalendarのVer.6から7への変更対応<br>
レスポンシブ対応<br>

## テストした内容
タスク名・期限日・期限時間をそれぞれ埋めずに追加ボタンクリックでアラート表示確認<br>
期限日・期限時間それぞれで現在の時刻より前を設定して追加ボタンクリックでアラート表示確認<br>
タスク名にHTMLタグが入力されたときにエスケープ処理されているか確認<br>
キーワード検索・完了・未完了・並び順それぞれ独立して動作すること確認<br>
キーワード検索・完了・未完了・並び順が複合しても処理が壊れないこと確認<br>
ソート・フィルター処理後に追加・削除しても配列が壊れないこと確認<br>
ソート・フィルター処理後に完了・未完了切り替えが正常にできること確認<br>
ソート・フィルター処理が件数表示に影響を及ぼさないことを確認<br>
ページを開きなおしてもソート・フィルター以外の現在の状態が保持されていることを確認<br>

## 起動方法
index.htmlをXAMPPサーバで開く
