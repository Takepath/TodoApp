# Level 4 README

## **Todoアプリ**

## アプリ概要
ブラウザで動作するTodo管理アプリ

## 主な機能
Todo追加・編集・削除  
Todoのソート・フィルター  
カレンダーイベントとの連携  
タブレットサイズ以下の画面でのTodo追加エリア非表示  

## 使用技術
HTML / CSS / JavaScript / FullCalendar7.1.0 / 祝日JSON API(https://holiday.omikuji.dev/api/) / PHP

## データ構造
<dl>
    <dt>Todoクラス : </dt>
    <dt>メンバ変数 : </dt>
        <dd>title : Todoの見出し。</dd>
        <dd>completed : Todoの完了状態管理フラグ。初期状態はfalse。</dd>
        <dd>dueDate : String型の日付。"2026-09-25"形式。</dd>
        <dd>dueTime : String型の時間。"10:00"形式。</dd>
        <dd>allDay : FullCalendarで使用する全日イベントフラグ</dd>
        <dd>createdAt : インスタンスが作成された時間。Dateオブジェクト形式。</dd>
    <dt>メソッド : </dt>
        <dd>なし</dd>
    <dt>Todo配列 : </dt>
        <dd>Todoクラスを格納する配列。</dd>
    <dt>util.STATE</dt>
        <dd>filter:タスクの完了、未完了で絞り込むフィルターステータス。all(すべて), non(未完了), fin(完了)</dd>
        <dd>deadline:タスクの期限内、期限切れで絞り込むフィルターステータス。all-dead(すべて), within(期限内), expired(期限切れ)</dd>
        <dd>sort:並び替えで使用するステータス。addition(追加順), long(期限が長い順), short(期限が短い順)</dd>
        <dd>keyword:絞り込み用キーワード</dd>
        <dd>display:container要素を表示するかのフラグ</dd>
</dl>

## API 構成
CRUDそれぞれ1つのPHPファイルで管理。すべてapiフォルダ配下。  
Create  →　create.php  
Read    →　get.php  
Update  →  update.php  
Delete  →　delete.php  

## API 通信の流れ
api　→　storage.js　→　各UI配下のJavaScriptとcalendar.js  
各UI配下のJavaScriptとcalendar.js　→　storage.js　→　api  

## 非同期処理について
storage.js配下の関数はすべてasync/awaitを使用して同期的に処理を行う  
上記影響からmain/calendarとUIフォルダ配下すべてでasync/awaitを使用  

## FullCalendar について
Ver.7.1.0を使用  
index.htmlにてCDNリンク読み込み  
calendar.jsにて具体的な処理実装  

## エラー処理
Todo登録・編集時に空欄が含まれていたらalert表示  
タスク名にHTMLタグが含まれていたらescapeHTML関数で置換  
読み込み先jsonファイルが破損していたらPHPからコンソールに通知  

## 工夫した点
Reactのようなコンポーネント指向プログラムを目指して作成した点  
STATEはutil.js配下のオブジェクトとして扱う  
保守性を高めるためにHTML作成関数とイベント追加関数を分離する等責任を明確に  

## 苦労した点
localStorageからAPI取得データに切り替える処理  
FullCalendarのVer.6から7への変更対応  
レスポンシブデザイン対応
